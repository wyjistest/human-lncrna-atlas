## 1) 本周（1 周）优先级：门禁稳定性 + 开发连续性

### 1.1 perf regression 稳定性再增强（P1）

目标：减少 self-hosted 环境的偶发抖动误报，同时保持“可定位”的门禁价值。

建议工作项（按优先级）：
1. **Genes/Regulations 指标稳定性**：在保持 `pct` 门禁的前提下，继续验证 `response_abs_ms` 的合理区间（避免因抖动触发误报）。
2. **warmup 请求策略**：对样例数据集（docker-sample）确保每次 run 都能稳定达到 `min_samples`（例如调整 warmup 路径/参数，使 endpoint 不被分页/过滤影响）。
3. **门禁报告可读性**：当门禁失败时，报告中明确给出“是否样本不足 / 是否存在 429 / 是否为首次运行导致 baseline 漂移”等高频根因提示。

验收标准：
- `Performance Overlap` / `Performance Genes/Regulations` 在 self-hosted（docker-sample, check）能稳定通过（连续多次运行无随机失败）。
- 失败时报告能给出明确、可操作的定位信息（而非仅阈值对比）。

### 1.2 GitHub 网络受限止损路径固化（P1）

目标：在 `git push` 不稳定时仍能保持“可审计、可回滚”的交付节奏。

建议工作项：
- 在 README 的 CI 部分提供明确入口链接（已完成），并补充“推荐优先级”：单次命令代理 → API 推送脚本 → 仅本地 CI。
- 对常见环境变量（`http_proxy/https_proxy/NO_PROXY`）给出最小可用模板（不建议写入全局 git config）。

验收标准：
- 新同学按文档可在 10 分钟内完成：本地跑 CI 门禁 + 推送到 GitHub + 核验 Actions。

## 2) 下周（2 周）方向：前端首屏体验 + Research 最小产出

### 2.1 前端 bundle/首屏体验（P2）

目标：控制首屏关键资源体积与加载顺序，避免大 chunk 回到首屏。

建议工作项：
- 定期记录 `npm run build` 的关键 chunk（`antd-vendor` / `igv-vendor` / `echarts-core` / `pdf-vendor`）体积与 `dist/index.html` 的 modulepreload 列表（作为回归锚点）。
- 评估将“非首页必须”的重依赖进一步延迟加载（例如只在进入对应页面时才触发加载/预取）。

验收标准：
- `npm run build` 通过；`frontend/web/scripts/check-entry-preloads.mjs` 的预算与允许列表保持可解释、能捕获明显回归。

### 2.2 Phase 6.0（Research Analysis）最小可重复产出（P2）

目标：对外输出一份“可复现”的分析结果（CSV/Markdown），并明确输入/运行方式。

建议最小交付：

验收标准：
