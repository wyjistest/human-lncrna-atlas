# Changelog - 2025-12-20

## Phase 9.13: Security Review Fixes

### Security Fixes

#### 1. LIKE Wildcard Bypass Prevention (High Priority)
**Problem**: `/export/disease-network` endpoint's "no filter fallback limit" could be bypassed with `trait_name=%` or similar wildcards, allowing full table exports and resource exhaustion.

**Solution**:
- Added `is_effective_like_filter()` function to detect pure wildcard patterns (`%`, `_`, `%%`, etc.)
- Apply `escape_like_pattern()` to all trait_name inputs
- Added `ESCAPE '\\'` clause to SQL ILIKE queries
- Pure wildcards now trigger the low-limit fallback (500 rows)

**Files Modified**:
- `frontend/backend/app/routers/export.py:55-72` - New helper function
- `frontend/backend/app/routers/export.py:550-565` - Filter detection logic
- `frontend/backend/app/routers/export.py:584` - SQL ESCAPE clause

#### 2. Sankey Visualization ILIKE Escaping (Medium Priority)
**Problem**: Sankey data's trait_name was directly concatenated into ILIKE queries without escaping, allowing wildcards to expand query scope unexpectedly.

**Solution**:
- Added `escape_like_pattern()` import and usage
- Added `ESCAPE '\\'` clause to SQL query

**Files Modified**:
- `frontend/backend/app/routers/visualization.py:14` - Import
- `frontend/backend/app/routers/visualization.py:113-115` - Escaping logic
- `frontend/backend/app/routers/visualization.py:151` - SQL ESCAPE clause

#### 3. species_ids Silent Fallback Prevention (Medium Priority)
**Problem**: When `species_ids` parsing failed, the code only logged warnings and ignored the filter. If all values were invalid, queries returned unfiltered results.

**Solution**:
- Added `raise_on_empty` parameter to `_parse_ids()` function (default: True)
- When all provided IDs are invalid, returns HTTP 400 instead of silent fallback
- Error message includes the invalid values for debugging

**Files Modified**:
- `frontend/backend/app/routers/regulations.py:220-256` - Enhanced `_parse_ids()` function

### Reliability Fixes

#### 4. Analysis Summary MV Graceful Degradation (Medium Priority)
**Problem**: Analysis summary hard-depended on `mv_lncrna_chipseq_overlaps` materialized view. If missing, triggered HTTP 500 and broke the entire page.

**Solution**:
- Added try-except around epigenetic query
- On failure, returns empty epigenetic data instead of 500
- Logs warning with guidance on creating the MV

**Files Modified**:
- `frontend/backend/app/routers/analysis.py:167-213` - Graceful degradation

#### 5. ETL Script Database Password Support (Low Priority)
**Problem**: `fix_chimp_empty_dna.py` didn't read database password, failing on password-protected production databases.

**Solution**:
- Added `DB_PASSWORD` environment variable support
- When password is empty, removes key to allow `.pgpass` or trust authentication

**Files Modified**:
- `etl/fix_chimp_empty_dna.py:25-36` - Password configuration

### Documentation

#### 6. Frontend Admin API Key Security Documentation (Low Priority - Deployment Risk)
**Problem**: Frontend injects `VITE_ADMIN_API_KEY` into build artifacts. If used in public deployments, the Admin Key would be exposed.

**Solution**:
- Added deployment scenario risk matrix to CLAUDE.md
- Added secure Nginx configuration example
- Added deployment checklist

**Files Modified**:
- `CLAUDE.md:173-201` - Security documentation section

### Design Principles Applied

1. **Fail-Fast Validation**: Parameter validation errors should return explicit errors, not silent degradation
2. **Graceful Degradation for Optional Dependencies**: Materialized views and similar optional components should degrade gracefully
3. **Defense in Depth**: Multiple layers of input validation (client-side, API, database)
4. **Security Documentation**: Deployment risks must be clearly documented with actionable solutions
