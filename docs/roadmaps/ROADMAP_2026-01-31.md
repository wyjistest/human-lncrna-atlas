# 未来 1–2 周路线图（可执行）

> **状态说明**: 本路线图为 2026-01-31 快照，现状以 `docs/CURRENT_STATUS.md` 为准。

目标：把“新机器可快速自举、回归可随时触发、文档不误导”变成默认工作流（小步提交、可审计可回滚）。

## 1) 本周（1 周）优先级：本地可复刻（P0）

### 1.1 本地服务最短路径（docker compose + localhost allowlist）

- 交付：
  - 在 `docs/LOCAL_CI_BOOTSTRAP.md` 补齐一段可直接用于本机的 `.env` 示例（`TRUSTED_HOSTS` / `CORS_ORIGINS` 指向 localhost/127.0.0.1）。
  - 明确“哪些门禁需要 DB/Redis”“哪些不需要”，并给出一条命令式入口。
- 验收标准：
  - 按文档执行后，`docker compose up -d` 可稳定启动 `postgres`/`redis`/`backend`；
  - `curl http://127.0.0.1:8000/health` 返回成功；
  - `bash scripts/run-tests.sh docs-check` 通过。

### 1.2 文档误导信号治理（持续）

- 交付：
  - 继续清理历史文档中容易被误读为“当前 backlog”的表述；
  - 对包含 TODO/checkbox/mock/stub/未实现/待实现 的文档，确保包含 `docs/CURRENT_STATUS.md` 指向“现状入口”（由 `scripts/check_docs_status_markers.py` 护栏约束）。
- 验收标准：`bash scripts/run-tests.sh docs-check` 通过。

## 2) 下周（2 周）方向：全量回归可随时触发（P1）

### 2.1 self-hosted 上的“全量回归”触发指南

- 交付：
  - 在 `docs/CI_SELF_HOSTED_RUNNER.md` 补齐“建议的每周全量回归触发方式”（workflow_dispatch 输入、可选 Postgres jobs、可选 Firefox smoke）。
  - 约束：默认行为不变（push/main 仍以 fast-ci 为主），避免增加日常成本。
- 验收标准：手动触发一次 `Tests` workflow，确认可按需启用更重的 job。

## 3) 执行与回滚策略

- 每个主题独立 commit（必要时独立分支/PR），确保可 `git revert <sha>` 回滚。
- 先对齐“证据与复刻”：优先补齐可观测/可回归工具，再做体验/性能迭代。
